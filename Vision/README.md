# 2026Crane_Maixcam

基于两台 Sipeed MaixCAM 的物品识别与位置匹配系统。上位机通过自学习分类器识别物品种类，下位机通过 YOLO 模型检测数字编号，两者协作完成"分类 → 检测 → 匹配 → 输出"的完整流程，最终结果通过 UART 串口发送给 STM32 主控。

## 系统架构

```
┌─────────────┐   UART串口    ┌──────────────────────┐   WiFi AP + TCP   ┌──────────────────────┐
│    STM32    │◄────────────►│    上位机 MaixCAM     │◄────────────────►│    下位机 MaixCAM     │
│   (主控)    │              │   main_maixcam.py     │                  │   Ci_maixcam.py       │
│             │              │  自学习分类 + 匹配     │                  │  YOLO 数字检测        │
└─────────────┘              └──────────────────────┘                  └──────────────────────┘
```

## 文件说明

| 文件 | 运行设备 | 说明 |
|------|----------|------|
| `main_maixcam.py` | 上位机 MaixCAM | 主程序。WiFi AP 热点、触摸屏 UI、自学习分类器（30帧投票）、TCP 服务端、UART 串口通信 |
| `Ci_maixcam.py` | 下位机 MaixCAM | 副程序。WiFi 连接上位机、YOLO 数字检测（30帧投票 + 4位置矩形匹配 + 缺失数字推理）、TCP 客户端 |
| `test_classify.py` | 上位机 MaixCAM | 调试工具。单独测试自学习分类器是否正常工作，显示识别结果和相似度 |

## 工作流程

### 1. 系统初始化

- **上位机**：启动 WiFi AP 热点（SSID: `maixcam`，密码: `12345678`，IP: `192.168.66.1`），启动 TCP 服务端监听 `0.0.0.0:9090`，加载自学习分类器，通过 UART 发送 `READY` 给 STM32
- **下位机**：连接上位机 WiFi 热点，TCP 连接 `192.168.66.1:9090`，加载 YOLO 模型，屏幕实时显示检测画面
- 上位机检测到下位机 TCP 连接后，屏幕显示绿色 `Slave: OK` + **START** 按钮

### 2. 用户点击 START

上位机同时执行两个动作：
- **TCP** → 下位机：发送 `START`，下位机开始 30 帧 YOLO 数字检测
- **UART** → STM32：发送 `start`，通知 STM32 流程开始

### 3. STM32 控制 3 次物品分类

STM32 每次把一个物品放到上位机摄像头前，然后发送 `s` 字符：

```
STM32 → UART → 上位机: "s"
                    ↓
上位机: 30帧自学习分类投票 → 得到分类结果（本地记录）
                    ↓
上位机 → UART → STM32: "SDONE"   （通知STM32本次分类完成，可以送下一个物品）
```

STM32 收到 `SDONE` 后，将下一个物品放到摄像头前，再发 `s`。重复 3 次后，上位机得到分类结果数组，例如 `cls_list = [2, 1, 3]`

### 4. 匹配

3 次分类完成后，上位机向下位机请求 YOLO 检测结果：

```
上位机 → TCP → 下位机: "QUERY"
下位机 → TCP → 上位机: "RESULTS:3,1,4,2,5"
```

上位机执行匹配计算：对每个分类结果，在下位机返回的数字数组中找到其位置（1-based）。

### 5. 输出结果

匹配结果通过 UART 发送给 STM32：

```
上位机 → UART → STM32: "MATCH:4,2,1"
```

上位机屏幕显示完整结果，用户可点击 **RESET** 按钮回到待机状态。

## 匹配算法

```
输入：
  分类结果 cls = [2, 1, 3]     （上位机自学习分类：绿豆、黄豆、白芸豆）
  检测结果 ocr = [3, 1, 4, 2, 5] （下位机 YOLO 检测 + 推理）

匹配过程：
  cls[0]=2 → 在 ocr 中找到 2 位于下标 3 → 位置 = 4（1-based）
  cls[1]=1 → 在 ocr 中找到 1 位于下标 1 → 位置 = 2（1-based）
  cls[2]=3 → 在 ocr 中找到 3 位于下标 0 → 位置 = 1（1-based）

输出：
  match = [4, 2, 1]
  含义：第1次分类的物品在位置4，第2次在位置2，第3次在位置1
```

## 下位机 YOLO 检测逻辑

下位机摄像头拍 30 帧，每帧使用 YOLO 模型检测画面中的数字（期望检测到 4 个，范围 1~5）。

### 位置判定

画面中有 4 个固定矩形区域，每个区域对应一个位置。检测框中心点落在哪个矩形内，就属于哪个位置：

```python
POS_RECTS = [
    (x_min, x_max, y_min, y_max),  # 位置1  ← 根据实际画面调试
    (x_min, x_max, y_min, y_max),  # 位置2
    (x_min, x_max, y_min, y_max),  # 位置3
    (x_min, x_max, y_min, y_max),  # 位置4
]
```

### 投票与推理

- 30 帧中每个位置取出现次数最多的数字
- 4 个位置各得到 1 个数字
- 第 5 个数字通过排除法推理：1~5 中没有出现的那个数字，自动放到结果数组最后一位

### 示例

```
YOLO 检测到 4 个数字：
  位置1 → 3    位置2 → 1    位置3 → 4    位置4 → 2
缺失数字：5
最终结果：[3, 1, 4, 2, 5]
```

## 上位机自学习分类器

上位机使用 MaixPy 内置的 `SelfLearnClassifier`（基于 MobileNet V2），支持 3 种物品分类：

| Class 编号 | 颜色 | 对应物品 |
|-----------|------|----------|
| Class 1 | 黄色 | 黄豆 |
| Class 2 | 绿色 | 绿豆 |
| Class 3 | 白色 | 白芸豆 |

### 训练方法

1. 运行 MaixCAM 自带的「自学习分类器」App
2. 对每种物品分别拍照添加样本（`+Class` 添加新类别，`+Sample` 添加样本）
3. 点击 `Learn` 学习
4. 保存后退出
5. 使用 `test_classify.py` 验证识别效果

### 分类过程

30 帧投票：每帧都从摄像头读取新画面，使用 `clf.classify()` 分类，最后取出现次数最多的结果。

## 通信协议

### UART 串口（上位机 ↔ STM32）

| 方向 | 消息 | 含义 |
|------|------|------|
| 上位机→STM32 | `READY` | 上位机就绪 |
| 上位机→STM32 | `start` | 用户点击 START，通知 STM32 开始流程 |
| 上位机→STM32 | `SDONE` | 每次 30 帧分类完成，STM32 收到后可送下一个物品 |
| 上位机→STM32 | `MATCH:<a>,<b>,<c>` | 最终匹配结果（3次分类全部完成后发送） |
| 上位机→STM32 | `ERR:NO_OCR` | 下位机检测获取失败 |
| STM32→上位机 | `s` | 物品已放好，请开始分类 |

### TCP（上位机 ↔ 下位机）

| 方向 | 消息 | 含义 |
|------|------|------|
| 上位机→下位机 | `START` | 开始 YOLO 扫描 |
| 上位机→下位机 | `QUERY` | 查询检测结果 |
| 上位机→下位机 | `PING` | 心跳检测 |
| 下位机→上位机 | `CONNECTED` | 下位机已连接 |
| 下位机→上位机 | `ACK:START` | 确认开始扫描 |
| 下位机→上位机 | `RESULTS:<a>,<b>,<c>,<d>,<e>` | YOLO 检测结果（5个数字） |
| 下位机→上位机 | `SCANNING` | 仍在扫描中 |
| 下位机→上位机 | `PONG` | 心跳回复 |

## 上位机状态机

```
STEP_IDLE (待机)
  │  屏幕显示 "Slave: OK" + [START] 按钮
  │  点击 START → TCP发START + UART发start
  ▼
STEP_WAIT_S (等待STM32发"s")
  │  屏幕显示 "Waiting for 's' from STM32..."
  │  收到 "s" → 进入分类
  ▼
STEP_CLASSIFY (分类中)
  │  30帧自学习分类投票（约1秒）
  │  分类完成 → 回到WAIT_S(3次未满)或进入MATCHING(3次完成)
  ▼
STEP_MATCHING (匹配中)
  │  TCP发QUERY请求下位机结果
  │  收到RESULTS → 匹配计算 → UART发MATCH:<a>,<b>,<c>
  ▼
STEP_RESULT (显示结果)
  │  屏幕显示 CLS / OCR / MATCH
  │  点击 [RESET] → 回到 STEP_IDLE
  ▼
  (回到待机)
```

## 调试用 UART 命令

除了主流程外，上位机还支持通过串口发送以下命令进行调试：

| 命令 | 响应 | 说明 |
|------|------|------|
| `QUERY` | `SENT:QUERY` 或 `ERR:NO_SLAVE` | 手动查询下位机结果 |
| `START_SLAVE` | `SENT:START` 或 `ERR:NO_SLAVE` | 手动触发下位机扫描 |
| `RESET` | `RESET_OK` | 重置上位机状态 |
| `STATUS` | `CLS=2 SLAVE=YES STEP=0` | 查询当前状态 |
| `PING` | `PONG` | 心跳检测 |

## 硬件需求

| 设备 | 数量 | 说明 |
|------|------|------|
| MaixCAM | 2 | 一台上位机，一台下位机 |
| STM32 | 1 | 主控，通过 UART 串口与上位机通信 |
| USB Type-C 转接板 | 2 | MaixCAM 串口引出（或直接使用 A16/A17 引脚） |

### 接线

**上位机 MaixCAM ↔ STM32**（UART 串口）：
- MaixCAM A16(TX) → STM32 RX
- MaixCAM A17(RX) → STM32 TX
- GND 连 GND
- 波特率：115200

**两台 MaixCAM 之间**：通过 WiFi 无线连接，无需接线。

## 依赖

- MaixPy 固件（MaixCAM 出厂固件）
- YOLO 数字检测模型（`.mud` 格式，需自行训练或获取，放到下位机 `/root/models/` 目录）
- 自学习分类器模型（通过官方 App 训练后保存到上位机 `/root/my_classes.bin`）

## 使用步骤

1. **训练自学习分类器**：在上位机 MaixCAM 上运行官方「自学习分类器」App，对黄豆/绿豆/白芸豆分别拍照训练并保存
2. **验证分类器**：将 `test_classify.py` 上传到上位机运行，确认识别准确
3. **准备 YOLO 模型**：训练或获取数字 1~5 的 YOLO 检测模型，放到下位机对应路径，修改 `Ci_maixcam.py` 中的 `YOLO_MODEL_PATH`
4. **配置位置矩形**：运行下位机程序，根据屏幕上的黄色矩形框调整 `POS_RECTS` 坐标
5. **运行主程序**：上位机运行 `main_maixcam.py`，下位机运行 `Ci_maixcam.py`
6. **连接 STM32**：确认 UART 通信正常
7. **开始使用**：点击 START 按钮启动完整流程
